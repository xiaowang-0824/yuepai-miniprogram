## 一、数据库集合权限（控制台配置，代码外）

> ⚠️ 此部分必须在微信云开发控制台手动配置，代码无法控制

| 集合 | 权限配置 | 原因 |
|------|----------|------|
| `users` | 仅创建者可读写 | 普通用户只能改自己的资料；`is_admin` 字段只能在控制台手动改，前端只读 |
| `schedules` | **仅云函数读写（禁止客户端直连）** | 档期是核心资源，前端直连可被篡改档期状态 |
| `orders` | 仅创建者可读写 | 用户只能看自己的订单；管理员通过云函数查全部 |
| `questionnaires` | 仅创建者可读写 | 问卷含客户隐私 |
| `works` / `portfolios` / `packages` / `equipment` / `pose_materials` | 所有用户可读，仅管理员可写 | 公开浏览，写入走 manage 云函数 |
| `theme_config` | 所有用户可读，仅管理员可写 | 主题配置公开 |

**简化安全方案**：所有集合设为「仅创建者可读写」，所有读写走云函数（云函数有 admin 权限绕过集合权限）。这样最安全， schedules 绝对不会被前端篡改。

## 三、时间与时区

### 3.1 定时任务超时判断

[timer/index.js#L12-14](file:///d:/约拍小程序/cloudfunctions/timer/index.js#L12-L14)：
```js
const now = Date.now();
const cutoff = new Date(now - timeoutMs);
// 查询 create_time: _.lt(cutoff)
```

**结论：无时区问题。**
- `create_time` 由 `db.serverDate()` 写入，存储为 UTC 时间戳
- `cutoff` 由 `Date.now()` 计算，也是 UTC 时间戳
- 两者比较基于时间戳，与时区无关，15分钟超时逻辑正常

### 3.2 日期区间生成

[utils.js#L79-87](file:///d:/约拍小程序/cloudfunctions/common/utils.js#L79-L87) `getDateRange`：

- `formatDate` 用 `getDate()` 本地时间方法
- 云函数运行在 UTC 或 UTC+8 都返回正确的 '2026-10-20'，**不会日期错位**

### 3.3 前端日期选择器

[booking.wxml#L54](file:///d:/约拍小程序/pages/booking/booking.wxml#L54)：

### 四、block 与 equip_lock 组合使用场景 — 【通过】

| 场景 | block.scope | equip_lock | 结果 |
|------|-------------|------------|------|
| A：本人有事，器材可租 | photo_only | 无 | 拍摄拦截，器材正常 |
| B：本人接单，器材带走 | 无 | 锁定器材 | 拍摄正常，锁定器材不可租 |
| C：外出，全停 | all | 锁定器材 | block 先拦截全部，equip_lock 不触发 |
| D：block(photo_only) + equip_lock 叠加 | photo_only | 锁定器材 | 拍摄被 block 拦，器材被 equip_lock 拦，各自独立 |

- 校验顺序固定：① block → ② equip_lock → ③ 档期冲突（[booking/index.js#L140-161](file:///d:/约拍小程序/cloudfunctions/booking/index.js#L140-L161)）
- equip_lock 仅对 `equipment_only` 订单生效，combo 订单的器材租赁不校验（拍摄订单自带器材优先级高于锁定）

### 五、状态机一致性 — 【通过】

- block/equip_lock 的 `status=1` 表示生效，删除时 `status=0, is_deleted=true`（走 deleteSchedule）
- 查询条件统一 `status: _.in([1])`（封锁/锁定不参与待支付锁定的 [1,2] 查询）
- getDaySchedules 返回4种类型列表（photo_list / equipment_list / block_list / equip_lock_list）
