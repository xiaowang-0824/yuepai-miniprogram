# 阶段3：云函数接口设计

> 版本：v1.1（已确认）
> 日期：2026-10-06

## 一、云函数总体架构

采用**模块化云函数 + action 路由**模式，目录清晰、冷启动可控。所有写操作和鉴权操作必须经云函数；公开内容读取可前端直连云数据库（只读），管理员/订单/档期操作全部走云函数鉴权。

**云函数清单（7个）**：

| 云函数 | 职责 | 是否鉴权 |
|--------|------|----------|
| `user` | 登录、用户信息、管理员判断 | 登录态 |
| `content` | 作品集/作品/套餐/器材/美姿 公开查询 | 公开 |
| `manage` | 管理员内容增删改（上述5类） | 仅管理员 |
| `booking` | 预约下单（档期校验+建单+问卷） | 需登录 |
| `order` | 订单查询/取消/状态流转 | 需登录（本人或管理员） |
| `schedule` | 档期查询/新增/释放/冲突校验 | 管理员 |
| `pay` | 沙箱支付下单/回调 | 需登录 |

**统一鉴权方式**：云函数内 `cloud.getWXContext().OPENID` 获取用户身份，查询 `users` 集合判断 `role`/`is_admin`。管理员接口未授权返回 `{code: 403, msg: '无权限'}`。

**统一响应结构**：

```js
{ code: 0, msg: 'success', data: {...} }      // 成功
{ code: 400, msg: '参数错误' }                  // 业务错误
{ code: 403, msg: '无权限' }                    // 权限错误
{ code: 500, msg: '服务器错误' }                // 系统错误
```

### 4. `booking` 云函数（预约下单核心）

| action | 入参 | 出参 data | 鉴权 | 说明 |
|--------|------|-----------|------|------|
| `checkSchedule` | `{date, type, equipment_ids?, rent_days?}` | `{available, conflict_reason?}` | 公开 | 档期预校验，执行顺序：①block封锁→②equip_lock锁定→③档期冲突 |
| `createOrder` | `{order_type, package_id?, equipment_items?, shooting_date, shooting_location, contact_name, contact_phone, remark?, questionnaire?}` | `{order_id, order_no, total_amount}` | 需登录 | 创建订单+问卷，校验档期 |

**createOrder 核心逻辑**：
1. 鉴权获取 user_id
2. **档期冲突校验**（再次校验，防前端绕过）：
   - 若 order_type 含拍摄（photo_only/combo）：查 `schedules` 中同默认摄影师、同 `date`、`schedule_type=photo`、`status in [1,2]` 的记录 → 存在则返回冲突
   - 若 order_type 含器材（equipment_only/combo）：对每个 equipment_id，查 `schedules` 中同 `equipment_id`、`schedule_type=equipment`、`status in [1,2]`、日期区间重叠的记录 → 存在则冲突
3. 校验套餐/器材状态（上架、未删除），取快照写入
4. 计算金额（套餐价 + 各器材日租金×天数 + 押金）
5. 生成订单号，写入 `orders`（status=pending_payment）
6. 若 questionnaire 非空且未跳过，写入 `questionnaires` 并关联 order_id
7. **不生成档期**（档期在支付成功后生成，符合需求"已支付订单自动生成档期"）
8. 返回订单信息，前端调起支付

> **档期软锁机制（待确认）**：createOrder 时对涉及的档期创建 `status=2`（待支付锁定）的 schedule 记录，15分钟未支付由定时触发器释放；支付时校验并转为 `status=1`（有效）。避免两人同时下单同一日期。

### 5. `order` 云函数

| action | 入参 | 出参 data | 鉴权 | 说明 |
|--------|------|-----------|------|------|
| `getMyOrders` | `{status?, page, pageSize}` | `{list, total}` | 需登录 | 当前用户订单，status 聚合查询 |
| `getOrderDetail` | `{order_id}` | `{order, questionnaire}` | 本人或管理员 | 订单详情+问卷 |
| `cancelOrder` | `{order_id, reason}` | `{}` | 本人或管理员 | 取消订单，释放档期 |
| `listAllOrders` | `{status?, page, pageSize}` | `{list, total}` | 仅管理员 | 全部订单 |
| `updateOrderStatus` | `{order_id, order_status}` | `{}` | 仅管理员 | 改状态（paid→in_progress→completed） |

**状态流转校验**：
- `pending_payment → cancelled`：允许
- `paid → in_progress`：管理员操作
- `in_progress → completed`：管理员操作
- 任意 → `refunded`：管理员操作（需先退款，一期沙箱直接改状态）
- 非法流转返回 400

**cancelOrder 逻辑**：
- 仅 pending_payment / paid 状态可取消
- 若是 paid 状态，释放关联档期（schedule status=0）
- 更新 order_status=cancelled，记录 cancel_reason

**状态聚合查询**：管理端"待处理"可聚合 `[pending_payment, paid, in_progress]`，避免页面与云函数对状态理解分裂。

### 6. `schedule` 云函数

| action | 入参 | 出参 data | 鉴权 | 说明 |
|--------|------|-----------|------|------|
| `getMonthSchedules` | `{year, month}` | `{list}` | 仅管理员 | 月历数据，返回该月所有档期 |
| `getDaySchedules` | `{date}` | `{photo_list, equipment_list}` | 仅管理员 | 某日档期详情 |
| `createManualSchedule` | `{schedule_type, date, end_date?, start_time?, end_time?, equipment_id?, customer_name, location, remark, block_reason?, block_scope?, lock_equip_ids?, lock_reason?}` | `{schedule_ids, count}` | 仅管理员 | 手动新增档期，支持 photo/equipment/block/equip_lock，支持连续多天批量创建；已有订单日期禁止新增 block/equip_lock |
| `deleteSchedule` | `{schedule_id}` | `{}` | 仅管理员 | 删除档期（手动档期直接删，订单档期需先取消订单） |

**冲突校验函数 `checkScheduleConflict`**（booking 和 schedule 共用）：

```
输入：{ date, schedule_type, equipment_id?, photographer_id? }
photo 冲突：同 photographer_id、同 date、type=photo、status in [1,2] 存在记录
equipment 冲突：同 equipment_id、日期区间重叠、type=equipment、status in [1,2] 存在记录
返回：{ conflict: boolean, reason? }
```

**新增校验函数**：
- `checkBlockConflict({dates, scope})`：查询 `schedule_type=block, status=1` 且日期落在 dates 内的记录。scope=equipment 时仅匹配 `block_scope=all`；scope=photo/combo 时匹配 `photo_only` 和 `all`。
- `checkEquipLockConflict({dates, equipIds})`：查询 `schedule_type=equip_lock, status=1` 且 `lock_equip_ids` 包含指定器材、日期落在 dates 内的记录。仅对独立器材租赁生效，拍摄订单自带器材不校验。

### 7. `pay` 云函数

| action | 入参 | 出参 data | 鉴权 | 说明 |
|--------|------|-----------|------|------|
| `unifiedOrder` | `{order_id}` | `{payment_params}` 或 mock 下 `{paid: true}` | 需登录 | 支付下单 |
| `payCallback` | `{out_trade_no, transaction_id}` | `{}` | 系统回调 | 支付回调，更新订单+生成档期 |
| `mockPay` | `{order_id}` | `{paid: true}` | 需登录 | 沙箱支付（前端直接调） |

**unifiedOrder 逻辑**：
1. 查订单，校验归属当前用户、状态为 pending_payment
2. 校验金额一致
3. **二次档期校验**：若此时有冲突（他人已支付），返回错误，订单自动取消
4. `IS_MOCK_PAY=true`（一期沙箱）：直接调用 mockPay 逻辑，标记订单 paid，生成档期，返回 `{paid:true}`
5. `IS_MOCK_PAY=false`（真实）：调用 `cloud.cloudPay.unifiedOrder`，返回支付参数

**支付成功后生成档期**：
- 若 order_type 含拍摄：创建 `schedule_type=photo` 档期（date=shooting_date，关联 order_id）
- 若 order_type 含器材：为每个器材创建 `schedule_type=equipment` 档期（date 区间，equipment_id，关联 order_id）
- 更新 order 的 schedule_ids 字段

**定时触发器**：配置 `timer` 触发器，每5分钟扫描 `pending_payment` 且超过15分钟的订单，自动取消并释放软锁档期。

## 三、通用业务校验规则汇总

| 校验项 | 位置 | 规则 |
|--------|------|------|
| 管理员鉴权 | manage/schedule 全部 action | `users.is_admin === true` |
| 档期冲突-拍摄 | booking.createOrder / schedule.createManual / pay.unifiedOrder | 同摄影师同 date 仅1条有效拍摄档期 |
| 档期冲突-器材 | 同上 | 同 equipment_id 日期区间不重叠 |
| 订单状态流转 | order.updateOrderStatus | 按状态机白名单，非法拒绝 |
| 金额校验 | pay.unifiedOrder | 订单 pay_amount 与计算值一致 |
| 软删除查询 | content 全部 | `is_deleted=false AND status=1` |
| 管理列表 | manage.list* | 不过滤 status（含下架），但过滤 is_deleted |

## 四、已确认的设计决策

1. **档期软锁机制**：采用「createOrder 创建 status=2 待支付锁定档期 + 定时触发器 15 分钟超时自动释放」方案。
   - 摄影预约单日唯一资源，软锁把冲突拦截在支付前，体验更好
   - 器材租赁同样纳入锁逻辑
   - 定时触发器每 5 分钟轮询清理超时 pending 订单
2. **支付方式**：一期仅启用沙箱 Mock 支付（`IS_MOCK_PAY=true`），保留真实微信支付完整代码骨架但关闭调用，二期再打开。
3. **管理列表权限**：`manage.list*` 系列接口仅限管理员调用。一期单人管理员版本，普通客户无投稿/器材发布需求。
4. **主题配置**：一期不做后台在线编辑主题色入口。4 套主题色预置写入 `theme_config` 集合初始化数据；后续改配色直接在云数据库手动修改集合记录，二期再加管理端主题编辑功能。

### 阶段3修正摘要

- `booking.createOrder`：下单成功立刻插入 `status=2`（待支付锁定）的档期记录
- `pay.mockPay / pay.unifiedOrder`：支付成功时，把对应锁定档期更新为 `status=1`（有效正式档期）
- 定时触发器：每 5 分钟执行，查找 `order_status = pending_payment` 且创建时间超过 15 分钟的订单，执行取消订单，并把关联 `status=2` 的锁定档期置为 `status=0`（释放）
- `checkScheduleConflict` 冲突判断条件：校验 `status in [1,2]`，正式档期和待支付锁定档期都视为占用
